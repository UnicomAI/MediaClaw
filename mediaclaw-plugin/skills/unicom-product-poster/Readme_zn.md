# unicom-product-poster 逻辑说明

这个文档是给人快速阅读的中文说明，用来帮助理解 `unicom-product-poster` 的执行逻辑。

## 1. Skill 的目标

这个 Skill 用来做“产品宣传海报”的多轮生成与优化，不是单次出图工具。

它的核心目标是：

- 根据产品介绍生成宣传海报
- 按固定评分表复评
- 根据低分项继续追问和优化
- 始终保留历史最佳版本
- 最终输出最佳海报

## 2. 整体流程

工作流固定为：

1. 整理海报 Brief
2. 打印本轮完整文生图 Prompt
3. 调用 `mediaclaw_text_to_image` 生成海报
4. 调用 `mediaclaw_image_qa` 打分
5. 展示评分表和趋势摘要
6. 如果未通过，则只针对最低分项继续优化
7. 如果通过，则输出最终最佳版本

## 3. 默认规则

- 默认画幅：`3:4`
- 默认风格：商业营销海报
- 默认每轮只生成：`1` 张
- 通过线：总分 `>= 75`
- 关键项必须 `>= 7/10`

关键项包括：

- 卖点清晰度
- 主视觉吸引力
- 产品主体突出度
- 信息层级与可读性

## 4. 为什么不会越改越乱

这个 Skill 有一个 `best_so_far` 机制，也就是“历史最佳版锁定”。

它会持续记录：

- 当前最佳图片
- 当前最佳总分
- 当前最佳 Prompt
- 当前最佳评分表
- 当前最佳保留优势

如果新一轮分数变低：

- 明确标记为回退
- 不覆盖历史最佳
- 后续继续从最佳版优化

所以它不是“每轮重新开始”，而是“基于最佳版本做保守增强”。

## 5. Prompt 是怎么处理的

每一轮调用 `mediaclaw_text_to_image` 之前，都会在对话里完整打印本轮 Prompt。

目的有三个：

- 方便追踪本轮到底改了什么
- 方便理解为什么分数会上升或下降
- 方便人工复盘和后续手工微调

从第 2 轮开始，Prompt 采用“增量修改”策略：

- 不重写整张海报概念
- 只修 1-2 个最低分项
- 显式保留已经做对的地方
- 禁止把历史强项改坏

现在还有一个很重要的变化：

- 内部仍然保留结构化 Brief
- 但真正发给文生图模型的最终 Prompt，必须改写成一段自然语言

也就是说，这个 Skill 现在分成两层：

### 内部 Brief

内部 Brief 仍然保留这些字段：

- 产品名称
- 产品类别
- 目标人群
- 核心卖点
- 3 秒信息
- CTA
- 品牌调性
- 颜色偏好
- 构图要求
- 禁止元素

这些字段主要用于：

- 多轮追问
- 评分复盘
- 回退比较
- 增量优化

### 最终 Prompt

真正送给 `mediaclaw_text_to_image` 的内容，不再是：

- `产品名称：...`
- `目标人群：...`
- `颜色偏好：...`
- `生成要求：1. 2. 3.`

而是改成：

- 一段完整自然语言
- 更像海报画面描述
- 更像 `Qwen-Image` 官方示例那种写法

例如它会更接近：

`生成一张高完成度的高端科技风产品宣传海报图，主角是一台……`

而不是字段清单。

## 6. 每轮会输出什么

每轮至少会在对话中展示：

- 当前轮次
- 工具调用过程
- 本轮完整 Prompt
- 本轮评分表
- 历史最佳分数
- 本轮分数
- 是否回退到最佳版

如果有多轮，还会显示一个轻量趋势摘要，例如：

- `总分趋势：72 -> 73.5 -> 65.5`
- `历史最佳：73.5（Round 2）`

## 7. 趋势图现在怎么生成

趋势图已经改成更简洁的规则：

- 不再单独保存每轮报告和最终报告
- 只在最后一轮对话里生成一次
- 只画“总分趋势”
- 使用 Mermaid `xychart-beta`

这样可以避免：

- 每轮重复出图
- 图表过密难看
- 关键项折线太多影响阅读

现在的趋势可视化分成两层：

### 对话层

只展示轻量文本趋势：

- `总分趋势：72 -> 73.5 -> 65.5`
- `历史最佳：73.5（Round 2）`

### 最后一轮对话层

只在最后一轮对话里放一张正式的 Mermaid 总分折线图。

## 8. 中文文案为什么要保守

这个 Skill 已经默认考虑了文生图模型对中文广告文案不稳定的问题。

策略是：

- 优先保住海报底图质量
- 优先保住版式和视觉层级
- 大标题可以尝试直接生成
- 小字、按钮文案、精确副标题不要过度依赖模型

换句话说，它更偏向：

- “高质量海报底图 + 可叠字版面”

而不是强迫模型一次性做出大量精确中文文字。

## 9. 为什么要改成单段 Prompt

这次改写的原因很直接：

- 字段清单更适合人看，不一定适合图像模型读
- 图像模型更擅长处理“连贯的画面描述”
- 海报任务本质上是视觉场景构造，不是表单填写

所以现在的规则是：

- 先用结构化 Brief 做内部推理
- 再把 Brief 压缩成一个面向画面的自然语言段落

这样通常更有利于：

- 主体稳定
- 构图集中
- 光线和氛围统一
- 海报感更强
- 文本区域表达更自然

## 10. 最终会输出什么

通过时：

- 最终最佳海报图片
- 如果是多轮，会在最后一轮对话里显示总分趋势图

未通过但用户停止时：

- 当前已接受的最佳图片
- 明确说明仍未过线
